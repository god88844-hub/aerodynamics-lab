# P0A-019: Component layout, materials, BOM and mass properties

Status **DEVELOPMENT / SOFTWARE VERIFICATION**. Physical acceptance remains **UNVALIDATED**. Base `688ab55` (`Merge pull request #143 from god88844-hub/feature/p0a-018-cad-editor-pbr`).

## Entry points and scope

- Authoritative layout & BOM assembly (`packages/physics/dynamics/assembly_layout.py`):
  - `build_multirotor_layout_and_bom(layout_spec, library)` resolves supported multirotor topologies (`quad_x`, `hex_x`, arbitrary symmetric/custom arm definitions `n_rotors >= 2`) against verified component records (`frame`, `motor`, `esc`, `battery`, `propeller`, `wiring`, `sensor`), computing full BOM metadata, `unverified_bom_items`, powertrain summary (`total_max_thrust_n`, `hover_throttle_estimate`), and total rigid-body mass, CoG, and inertia tensor via `mass_properties.py`.
  - Fail-closed `ValueError` refusal when custom solids lack `material_density_kg_m3` or provenance `source`.
- CLI & desktop UI integration:
  - `scripts/lab_project.py layout-bom --input ... --output ...` updates project snapshot/mass properties and exports authoritative BOM JSON.
  - `apps/desktop/main.gd`: `_open_layout_editor`, `_apply_layout_bom`, and `_process` handler for `layout-bom` render BOM count, rotor count, CoG, mass, and `unverified_bom_items` from the same authoritative JSON output.
