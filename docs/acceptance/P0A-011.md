## Shared canonical detector and desktop/offline boundary

- `packages/physics/validation/uav_fd_fault_detector.py` is the canonical physics detector. `calibrate(training)` consumes exactly two healthy whole-flight recordings (`NO_FAULT1.mat`, `NO_FAULT4.mat`); every other identity and missing calibration refuse.
- `evaluate(fit, electrical, vibration, expected_electrical_windows=..., expected_vibration_windows=..., onset_s=None, deadline_s=None)` consumes qualified window streams, so headless desktop telemetry adapters and offline campaigns use the same scoring/decision code. The desktop application has **not** yet been wired to a normal in-app fault-detection UI/stream; do not claim tested desktop integration.
- `DETECT`: fault class (ESC deficit/increased-load/own-motor 1P excursion), ESC-channel attribution, first exceedance and confirmation seconds, deadline and compliance status. Shared-IMU RPM-associated 1P bands overlap; no causal physical rotor isolation is claimed.
- `NO-ALERT`: only after both required channels have at least six eligible windows, each has at least 25% of declared coverage, and there is no confirmed trained excursion.
- `INCONCLUSIVE`: uncalibrated/invalid training fit, missing channel, unsupported RPM, insufficient eligible windows or coverage, invalid timestamps/data. Fault-onset unknown yields deadline-compliance `NOT_ASSESSABLE_NO_FAULT_ONSET`, not a fabricated latency success.
- Train-only per-ESC median speed-normalized electrical reference (W/(RPM/6000)^3), separate increased-load and deficit residuals. Train-only per-ESC RPM-associated 1P amplitudes normalized by own RPM squared, not maximum across six motors. No broad accel-RMS alert channel.
- Train-only higher-interpolated p95 per ESC per direction. Predeclared bounded two-exceedances-in-five-window confirmation. Nonadjacent threshold crossings on the same ESC can confirm; isolated crossings cannot. The 0.8 threshold release fraction is reserved for an eventual post-confirmation latch; no streaming clear/rearm is claimed in this version. This policy was chosen before any repaired holdout replay, but **it is DEVELOPMENT rather than prospectively validated**.
