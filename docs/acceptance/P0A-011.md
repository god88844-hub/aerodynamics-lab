# P0A-011 — Canonical M25 fault detection without label leakage

**Software implementation status:** DEVELOPMENT implementation verified against eight original publisher recordings; no operational or physical acceptance. **Base:** approved P0A-010 commit `a1cb76825d4bf5208ed75fb8542d4c566a4b04d8`. **PR:** [#135](https://github.com/god88844-hub/aerodynamics-lab/pull/135).

## 1. Shared entry points and three-state contract

The authoritative detector is `packages/physics/validation/uav_fd_fault_detector.py`, not a fork of an offline scoring script. Import via `from physics.validation.uav_fd_fault_detector import calibrate, evaluate` with `packages/` on Python's path. The standalone desktop's local Python runtime can import this same API; **a live desktop telemetry/UI integration has not been demonstrated by this campaign**. The source-pinned offline MAT ingestion adapter is `scripts/benchmark_p0a_011_uav_fd.py`. Original M25 scoring scripts, plans, thresholds, frozen JSON results, P0A-009 and P0A-010 acceptance documents remain untouched.

- `calibrate(training: Mapping[str, TrainingFlight])` admits **exactly** healthy whole recordings `NO_FAULT1.mat` and `NO_FAULT4.mat`. Missing, additional or holdout identities refuse. The resulting fit includes per-ESC training centers, directional p95 excursion thresholds, envelope, confirmation policy and provenance; no ground-truth fault labels enter calibration.
- `evaluate(fit, electrical, vibration, *, expected_electrical_windows, expected_vibration_windows, onset_s=None, deadline_s=None)` receives already qualified two-second windows and returns a JSON-compatible dict. `DETECT` names the measured signal-excursion **class**, channel and `ESC_i` association, first exceedance and confirmation timestamps, deadline parameter and compliance. `NO-ALERT` requires both channels, at least six eligible windows each, at least 25% channel coverage and no confirmed excursion. `INCONCLUSIVE` is required for absent/invalid fit, missing channels, unsupported source telemetry, out-of-envelope RPM, inadequate windows or coverage, malformed timestamps or values.
- The source publisher names (M1, M3, M4, M5) are **recording-level ground truth**, not inferred physical fault labels emitted by the detector. `ESC_i` means measured telemetry channel, **not a proven motor/rotor location**. Shared-IMU 1P bands can overlap and must not be described as physical isolation.
- Without a measured in-flight fault-onset instant, deadline compliance is `NOT_ASSESSABLE_NO_FAULT_ONSET`. The displayed first-exceedance/confirmation seconds are relative to each qualified channel recording's window clock, **not measured fault-to-detection latency**.

## 2. Train-only signal repairs and bounded persistence

Healthy calibration uses the two whole healthy training flights exclusively: electrical windows 20 + 23; vibration windows 20 + 21. Electrical centers are per-motor medians of `Volt*Curr / (RPM/6000)^3`. Both increase-load and power-deficit residuals are scored against the same motor's own healthy center. The competing rotor-order method scores each motor's *own* RPM-associated 1P band of three-axis detrended IMU acceleration (Lomb–Scargle), normalized by that motor's RPM squared, not the largest across-motor frequency bin. The broad accel-RMS baseline is **retired as an active detector**. All thresholds are higher-interpolated per-channel p95s of training windows only; no holdout class, decision or confusion value is an input.

A fixed, predeclared bounded **2-of-5-window, same-ESC and same-direction confirmation** allows nonadjacent positive windows and rejects isolated spikes. The policy declares a 0.8 lower release fraction, but this version is a **whole-recording first-confirmation decision**, not an implemented continuous streaming clear/rearm latch; therefore no post-alert hysteretic rearming is asserted. The train-only eligible median-RPM envelope is [5377.5, 6148.75]. An unsupported, non-scored sample cannot silently become a negative physical clearance.

## 4. Reproduction, tests and acceptance boundary
