## 2. Candidate causes audited one by one

**(a) Coordinate axes & thrust-normal conventions — RULED OUT (structurally).**
The prediction path contains no axis, normal, or unit handling at all:
`read_table` returns the publisher's raw `J, CT, CP` floats and every
prediction is a linear interpolation of those same columns
(`scripts/benchmark_uiuc_axial_sweeps.py` — asserted structurally by the
acceptance test: no density/diameter/radian/force-scaling vocabulary exists in
the script, and the only RPM use is the dimensionless blend weight
`(rpm − low_rpm)/(high_rpm − low_rpm)`). A convention mismatch cannot change a
sign that is never recomputed.

**(b) Advance-ratio J definition and windmilling transition — RULED OUT.**
J is the publisher's own column, consumed verbatim; the model never recomputes
`V/(nD)`. The `upper_plane_seam_j = 0.388` seam only assembles the upper
calibration plane (6,707 rows below it, 6,710 rows at/above it) and does not
touch the J = 0.671 neighborhood; the offending row is scored in the interior
of the common calibration range (J ∈ [0.146, 0.684]).

**(c) RPM / rad/s / RPS conversions and ρ/D scaling — RULED OUT.**
RPM enters only as the dimensionless blend weight 0.744590346; no
rev/s↔rad/s conversion, no ρ n² D⁴ scaling exists anywhere in the benchmark
(the physical thrust scale appears in this document only as a declared
UNVERIFIED_ESTIMATE for magnitude illustration).

**(d) Thrust/power sign definitions — CONSISTENT, no flip.**
The source's CT is signed (negative = windmilling past zero-thrust J); the
benchmark preserves signs end-to-end (`predicted_ct − ct` signed errors; the
disagreement test `(predicted_ct <= 0) != (ct <= 0)`). The static_reference
model shows the same single disagreement (it predicts +0.098 — static thrust
is always positive, blind to the zero crossing), while advance_ratio_only
agrees in sign (−0.000771) purely because its fixed 50/50 blend places the
zero crossing at J ≈ 0.6668 — just below 0.671. If a sign flip existed in the
pipeline, all three models and the whole high-J tail would disagree, not one
row.

**(e) Near-zero crossing & measurement resolution — ROOT CAUSE.**
The source tables carry CT to **4 decimal places**, so the recorded −0.0001 is
**exactly −1 count** of the publisher's format — the smallest nonzero
magnitude the file can express. The 6,018 RPM sweep crosses zero thrust
between its own samples (J = 0.647 → +0.0044; J = 0.671 → −0.0001; J = 0.697 →
−0.0048): interpolated zero crossing at **J ≈ 0.67047**. The RPM-blended
calibration interpolator (planes at 4,005 and 6,708.5 RPM, crossings at
J ≈ 0.65594 and J ≈ 0.67767) places its crossing at **J ≈ 0.67212** — a ΔJ of
**0.00165 (0.25 % of J)**. At J = 0.671 — one table count below the model's
crossing — the model outputs +0.000218 while the measurement records −0.0001.
In thrust terms (declared UNVERIFIED_ESTIMATE, ρ = 1.225 kg/m³ assumed,
D = 0.254 m, n = 100.3 rev/s): one CT count ↔ ≈ 0.0051 N (≈ 0.5 gf); the
signed error ↔ ≈ 0.016 N (≈ 1.7 gf). Both values are zero within the source's
resolution.

## 3. Root cause (evidence-backed)

**`resolution_limited_zero_crossing_straddle` — NOT a code, sign, unit, or
axis defect.** The row is the first sampled point past a real zero-thrust
crossing; the recorded −0.0001 is one count of the 4-decimal source format
(|T| ≈ 0.5 gf assumed-density scale), and the interpolator's zero crossing
differs from the measured one by ΔJ ≈ 0.0017 (0.25 %) because it interpolates
between calibration planes measured 2,700 RPM apart. The measured sign at
±1 count carries no physical information; declaring it a model sign error
would be a resolution artifact.

**Discriminating check** (recorded for completeness): re-measure CT at
J ∈ [0.66, 0.68] with resolution ≤ 0.00005 (½ count) and report the crossing
J — this requires new wind-tunnel data and belongs to the physical
measurement backlog, not to a software repair. The existing data cannot
distinguish the sign of a ±1-count observation.

## 4. Repair specification for P0A-009

P0A-009 ("Correct and verify the supported signed aerodynamic regime") should
implement, using this diagnosis:

1. **Resolution-aware sign classification**: a CT sign disagreement where
   |measured CT| ≤ 1 source-table count (0.0001) AND |predicted CT| ≤ 10
   counts (0.001) is reported as `sign_disagreements_resolution_limited`,
   never as a hard disagreement; hard disagreements require |measured CT|
   beyond the source resolution.
2. **Per-row predictions in the results artifact** so future audits never
   re-derive interpolations.
3. **Predeclared sign-resolution and uncertainty rules** for M24 acceptance,
   declared before scoring, scoring only inside the supported envelope
   (J ∈ [0.146, 0.684] for this propeller); any extrapolation outside the
   supported signed regime is refused or explicitly labeled.
4. The signed-regime implementation itself (sign preservation end-to-end,
   analytic frame/force checks) per the planned P0A-009 todos — the existing
   benchmark already preserves signs; the repair is the resolution-aware
   acceptance rule plus the regime contract.
