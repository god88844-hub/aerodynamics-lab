# P0A-007 — Verify battery replay versus prospective endurance behavior

**Status**: DONE · **Actor**: builder · **Date**: 2026-11-22 · **Commit under audit at start**: `4580d53`

## Mode separation (never blended)

`tests/acceptance/test_p0a_007.py` implements two scoring functions with
disjoint metric namespaces, and the separation is asserted mechanically:

- **MODE A — measured-current replay** (`replay.*` keys): current is SOURCE
  DATA (trapezoid quadrature of the measured samples — the frozen M21 charge
  convention). The model only tracks loaded voltage, SOC and cutoff timing.
- **MODE B — prospective endurance / forecast demand** (`prospective.*`
  keys): current is MODEL OUTPUT from the exact causal constant-power
  quadratic (`BatteryPack.solve_constant_power`), charge advanced at the
  start-of-tick state, cutoff bracketed per step, no post-cutoff energy or
  state.

`REPLAY_METRICS ∩ PROSPECTIVE_METRICS = ∅` is asserted at import time and per
call; no combined replay+prospective score exists in the module. The same
scoring functions run on committed/analytic data (CI-unconditional) and on
the pinned workbook rows (opt-in), so the separation is not scenario-specific.

## Conservation (solution verification — exact identities)

Charge and energy balances are exact identities of the implemented equations,
verified for both modes and recorded per run:

| Identity | Case | Residual |
| --- | --- | ---: |
| `ΔSOC·C/100 = ∫I dt` (replay, constant 2.5 A × 600 s) | internal accounting | 5.6e-17 Ah |
| `ΔSOC·C/100 = ∫I dt` (replay, variable current) | internal accounting | 0.0 Ah |
| `E_ocv = E_bus + E_loss,R` (replay, constant) | same quadrature weights | 7.6e-17 Wh |
| `E_ocv = E_bus + E_loss,R` (replay, variable) | same quadrature weights | −6.7e-16 Wh |
| `ΣI·dt = ΔSOC·C/100` (prospective, 60/120 W) | internal accounting | < 1e-12 Ah |
| `E_ocv − E_bus = E_loss,R` (prospective, 60 W × 60 s) | recomputed per step | rel 1e-9 |
| Workbook replay rows (99 cycles) | `replay.charge_balance_ah` max abs | 8.9e-16 Ah |
| Workbook replay rows (99 cycles) | `replay.energy_balance_wh` max abs | 1.2e-13 Wh |

The energy decomposition uses the SAME quadrature weights for all three terms;
the caller-owned polarization state (when present) enters the identity as
`E_ocv = E_bus + E_loss,R + E_rc`.

## Defects caught during verification

1. **Replay-scorer polarization defect (test tooling, this task)**: the first
   implementation subtracted `rc·I_raw` instead of the caller-owned filtered
   polarization state, producing 36 false alarms that contradicted the frozen
   screen. Fixed by making `V_rc` an explicit per-sample caller-owned state —
   matching `battery.py`'s declared causal contract. The frozen protocol's
   filtered-state convention is now explicit at the call site.
2. **Prospective endpoint-SOC metric defect (test tooling, this task)**: the
   endpoint used the record's final measured charge instead of the charge at
   forecast issue, producing negative endpoint SOCs. Fixed to the issue-time
   state.
3. **No defects in `packages/physics/propulsion/battery.py` or the plant were
   uncovered**: all conservation identities are exact by construction, the
   convergence is clean (O(dt²) replay, O(dt) prospective bracketing), and
   the declared-support/collapse contracts held under every case. `battery.py`
   is UNCHANGED by this task (it was a listed target reserved for defect
   fixes).
