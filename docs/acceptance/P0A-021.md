# P0A-021: Repeatable engineering test ground authoring

Status **DEVELOPMENT / SOFTWARE VERIFICATION**. Physical acceptance remains **UNVALIDATED**. Base `688ab55` (`Merge pull request #143 from god88844-hub/feature/p0a-018-cad-editor-pbr`).

## Entry points and scope

- Authoritative test-ground schema & validator (`packages/desktop_worker/environment_authoring.py`):
  - `TestGroundObstacle`, `LandingSurface`, `TestGroundSpec`, `validate_supported_environment`, `author_test_ground` serialize terrain, obstacles, landing surface, 3D wind vector (`m/s`), temperature (`K`), pressure (`Pa`), and relative humidity (`0..1`) with declared world origin (`NED`/`ENU` explicit frame) and units.
  - Fail-closed refusal on unsupported mechanisms: precipitation (`rain_mm_h > 0`, `snow_mm_h > 0`, `icing_enabled`), unsupported atmospheric regimes, or unsupported contact models (`soft_soil`, `water`, `moving_deck`, etc.).
- Worker & desktop PBR UI integration:
  - `scripts/lab_project.py author-ground` saves validated ground parameters inside the project document for save/reload identity.
  - `apps/desktop/main.gd`: `_open_test_ground_dialog`, `_apply_test_ground`, and display-only PBR cues (`_refresh_ground_props` rendering `ground_props` pad and obstacles strictly isolated from aerodynamic/contact physics).

## Limitations and exclusions

- Supports rigid dry flat/sloped ground and static box obstacles only; weather/precipitation, dynamic wind turbulence spectra, and deformable ground contact remain unsupported/refused until later slices.
