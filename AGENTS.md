# Builder entry point

Read [the product specification](docs/PRODUCT_SPEC.md), [roadmap](docs/ROADMAP.md) and [acceptance ledger](docs/ACCEPTANCE.md) before selecting work. Phase 0 is the current implementation focus. The ledger identifies existing capabilities, pending work and evidence gaps.

Follow [the architecture and legacy boundary](docs/ARCHITECTURE.md). `apps/web` is frozen legacy: security fixes and minimal CI/compatibility corrections only. No new WP7–WP9 implementation, full WP3 CAD expansion or physics-failure tuning is authorized until the WP1–WP3 contracts and prototype qualification have been reported and the owner has signed off.

For data/model work, read [the source library](docs/SOURCES.md) and the applicable campaign report. Record the original source identity, actual bytes, license, hardware, conditions and uncertainties used by the change.

For architecture changes, follow the shared contracts and migration/prototype gates in the specification. Reuse verified existing behavior and record new acceptance evidence through normal entry points.

Preserve legacy milestone reports as history. Update current requirement status with verifiable commit, CI or experiment links when delivering a package.
